# PRIVACY

IntakeMint はクライアント名・メール・提出ファイル・業務資料を扱う。

## データ最小化と利用目的
- 回答本文・ファイル内容を分析ツール（Analytics）や学習に流用しない。監査ログ・通知・メール本文には本文を大量に載せない（監査は ID・件数・理由のみ）。
- リマインドメールには「項目名と状態」のみ（回答内容は含めない）。
- パスワード・マイナンバー・医療情報などを集めない運用を推奨（SNSサンプルには「パスワードを入力しない」同意項目）。

## AI
| 設定 | 効果 |
|---|---|
| 組織 AI ON/OFF（設定 → AIとプライバシー） | OFFで全案件のプロバイダ呼び出し0、`ai_documents` を削除 |
| 案件 AI ON/OFF | 同上（案件単位） |
| ファイル単位 AI 除外（クライアント/内部） | そのファイルのテキストをAIに渡さない・AI index から削除 |
| 外部AI送信 | 既定は不可。`AI_ALLOW_EXTERNAL=true` を運用者が設定した場合のみ。**実個人/機密データを外部AIへ送る前に、顧客との合意（DPA等）と人間の承認が必要** |
Anthropic API は既定で学習に使われず30日以内に削除（一部モデルは30日保持・ZDR不可）— SOURCE_NOTES.md 参照、契約前に再確認。

## 保存期間と削除
- `retentionDays`（既定365日）経過したアーカイブ/キャンセル案件をジョブが自動削除（回答・ファイル原本・AI index・検索index）。
- 案件の完全削除（Manager以上）：回答・ファイル（オブジェクト含む）・AI index・検索index・候補・パックを削除。監査ログには内容を含まない削除記録のみ残す（テスト #24）。
- AI index（`ai_documents`）は案件削除・AI OFF・ファイル除外で削除。

## エクスポート / 削除請求
- 案件の回答CSV（数式インジェクション対策済み）、組織全体のZIPエクスポート（Owner/Admin）。
- クライアントからの削除依頼は担当者が案件削除で対応（クライアント自身の削除UIは「確認前の自分のアップロード」のみ）。

## クライアントのアクセス
アカウント不要・期限付き・失効可能なリンク。トークンはハッシュのみ保存。`Referrer-Policy: no-referrer` でURL漏えいを防止。ログ出力時はトークンをマスク。

## 端末
オフライン下書きはブラウザの localStorage に回答のみ保存し、送信成功で削除。共有端末での利用は注意喚起が必要（注意事項.txt）。
