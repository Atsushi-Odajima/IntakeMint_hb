案件開始パック
========================================

■ 案件開始パックとは

お客様から集めた回答・ファイル・確認結果を、仕事を始める人（制作担当、外注先、Claude Code など）が
そのまま読める形にまとめた資料です。案件詳細の「案件開始パック」タブで作ります。

・「パックを生成」を押すと、その時点の内容でパックが作られ、v1、v2…と履歴が残ります。
・Ready でない案件でも生成できますが、「この案件はまだReadyではありません。生成できますが、
  未確定事項（Unknown / Open Questions）を含みます。」と表示されます。
・生成には「パック生成」権限（Owner / Admin / Manager / Editor）が必要です。


■ パックの構成（13セクション）

・Client（クライアント）……… クライアント名、会社名、連絡先など
・Project（案件）……………… 案件名、必要な機能、公開希望日など
・Objective（目的）…………… サイト・依頼の目的
・Audience（対象）…………… ターゲット
・Requirements（要件・回答）… 事業内容や仕様に関わる回答
・Preferences（要望）………… デザインの好みや要望
・Assets（素材）……………… 提出されたファイル（参考資料以外）
・References（参考）………… 参考サイト、分類が reference のファイル
・Constraints（制約）………… 期限・予算・準備完了目標日
・Open Questions（未解決事項）… まだ揃っていない項目、回答待ち・確認待ちの追加質問
・Files（提出ファイル）……… 差し戻し以外の全ファイルの一覧（保存パス・承認状態・サイズ）
・Decisions（確認・決定事項）… 確認済みの追加質問、内部サインオフ、Ready上書きの記録
・Notes（メモ）……………… どのセクションにも割り当てていない回答、担当者のレビューメモ

空のセクションは出力されません。どの質問をどのセクションに入れるかは、フォーム編集画面の
「パック構成」タブで設定します（割り当てていない回答は Notes に入ります）。


■ 出典（ソース）付き

各行の末尾に、その情報がどこから来たかが付きます。
・[q:質問ID] ………… 例 [q:site_goal]（どの質問の回答か）
・[file:ファイルID] … ファイルIDの先頭8文字
・[followup:…] ……… 追加質問
・[review:…] ………… サインオフ・上書きの記録
・[item:…] …………… 必要項目や案件情報（クライアント名など）

「この要件は本当にお客様が言ったことか？」を、いつでも元の回答までたどれます。


■ Unknown と Open Questions

・パックは、回答にない要件を作りません。AIが内容を補ったり、推測で書き足したりもしません。
・割り当てた質問が未回答の場合は「Unknown（未回答）」と表示されます。
・揃っていない必要項目は Open Questions に「未提出」「一部提出（3/5）」のように並びます。
・回答はあるが担当者が確認していない追加質問は「→ 回答: 〜（未確定）」として Open Questions に入ります。
・条件分岐で非表示になった質問の回答は、パックに含まれません。


■ 出力形式

生成後に表示されるボタン
・Markdown … .md ファイルをダウンロード
・TXT ……… 記号を取り除いたテキスト
・JSON …… 機械処理向け（schema: intakemint.package/v1。全セクションと出典をそのまま含みます）
・コピー …… Markdown をクリップボードへ（Claude Code にそのまま貼り付けできます）
・印刷 / PDF保存 … ブラウザの印刷機能を開きます。印刷先で「PDFに保存」を選ぶとPDFになります

「生成履歴」から過去のバージョンを「表示」したり、「MD」でダウンロードしたりできます。
ファイルの実体はパックに含まれません（Files に保存パスと情報が載ります）。
ファイル本体が必要な場合は、案件画面から個別に開くか、組織のバックアップZIPを使ってください。


■ Handoffプロファイル

パックの後半には、受け取る人の職種に合わせた「Handoff」が付きます。
プロファイルは次の8種類です（パック生成時にプルダウンで切り替え可能。既定はフォームの設定）。

・Web Development（Claude Code向け）
・Design
・Video
・SNS Management
・Consulting
・Recruiting
・Accounting Prep
・Generic

Handoff の構成
・Overview ……………… 案件・目的・対象
・Pages / Features（候補）… Web Development のみ。選ばれた機能から導いたページ候補
・Brand Assets / Assets … 素材
・Content ………………… 要件と要望
・References / Constraints / Open Questions / File Paths
・Acceptance Criteria（候補）… 必要項目から機械的に作った確認観点の候補

「候補」と付いた部分は、技術仕様やページ構成、正式な受入基準として確定したものではありません。
最終的な内容は担当者が決めてください。
