Backup・Export（バックアップとエクスポート）
========================================

■ 組織の全データをバックアップする

・「設定 → バックアップ・エクスポート」→「全データをエクスポート」を押すと、
  intakemint-backup-（日付）.zip がダウンロードされます。
・エクスポートには Owner / Admin 権限が必要です。
・実行したことは監査ログに記録されます。

ZIPに含まれるもの
・テンプレート（全バージョン）、案件、回答、提出ファイルの実体、レビュー、AI候補、追加質問、
  リマインド、メール送信履歴、通知、案件開始パック、監査ログ、メンバー情報 など
・manifest.json
  - format（intakemint.backup）
  - schemaVersion（データ構造のバージョン）
  - appVersion（アプリのバージョン）
  - exportedAt（作成日時）、件数、checksums（全ファイルのチェックサム）
  - 関係性の指紋（復元後にデータのつながりが壊れていないかを確認するための値）

ZIPに含まれないもの（意図的に除外）
・ログイン中のセッション、MCP / APIトークン、処理待ちのジョブ、AI用の抽出テキスト（AIインデックス）
  → 復元後は、各自ログインし直し、APIトークンは作り直してください。


■ 復元する（空の環境へ）

  npm run restore -- backup.zip

・復元先は「その組織がまだ存在しない、空の環境」です。同じ組織がすでにあると
  「同じ組織がすでに存在します。空の環境に復元してください」と表示されて中止します。
  （サンプルデータ入りの環境や、同じユーザーが登録済みの環境への復元は避けてください）
・復元コマンドは、復元先のサーバーと同じ環境変数（DATABASE_URL、PGLITE_DIR、STORAGE_DIR、S3_* など）
  で実行してください。PGlite を使っている場合は、サーバーを停止してから実行してください。
・復元時に次を自動チェックします。
  - 中身がIntakeMintのバックアップか（manifest.json の format）
  - アプリより新しい schemaVersion ではないか（新しい場合は「アプリを更新してください」）
  - すべてのファイルのチェックサムが一致するか（1つでも違えば中止）
  - 不正なパスを含まないか、展開後のサイズが大きすぎないか
・完了すると件数と結果（JSON）が表示されます。関係性の指紋が一致しない場合は
  「WARNING: relation fingerprint mismatch」と表示され、終了コード2になります。その場合は
  復元先の状態を確認し、必要なら空の環境でやり直してください。


■ 案件ごとのCSV出力

・案件詳細「回答」タブの「CSV出力」で、case-responses.csv をダウンロードできます。
・内容
  - 前半：section / question_id / question / visible / answer（質問ごとの回答）
    非表示の質問は visible 列が「no(hidden)」になります
  - 後半：item_id / item / status / count / min（必要項目ごとの状態）
・Excel で文字化けしないよう、UTF-8（BOM付き）で出力します。
・数式インジェクション対策済み：= + - @ タブ 改行 で始まるセルは、先頭に ' を付けて
  Excel で数式として実行されないようにしています。


■ そのほかの書き出し

・案件開始パック：Markdown / TXT / JSON / 印刷・PDF保存（「案件開始パック.txt」参照）
・ファイル：案件詳細でファイル名を押すと、5分間有効なURLで開けます


■ バックアップの保管について（重要）

・バックアップZIPには、お客様の個人情報や業務資料がそのまま含まれます。ZIP自体は暗号化されていません。
・必ず暗号化されたストレージ（暗号化ディスク、暗号化を有効にしたクラウドストレージ等）で保管し、
  アクセスできる人を限定してください。
・メール添付やチャットでの共有は避けてください。
・不要になった古いバックアップは削除してください。
・アーカイブ・キャンセルした案件は保存期間（既定365日）を過ぎると自動削除されます。
  削除後に必要になる可能性があるデータは、事前にバックアップしておいてください。


■ おすすめの運用

・定期的（例：毎週）に全データをエクスポートして、暗号化ストレージへ保存
・PostgreSQL を使っている場合は、データベース側のバックアップ（ポイントインタイムリカバリ等）も併用
・年に1回程度、空の検証環境へ実際に復元して、手順と中身を確認
